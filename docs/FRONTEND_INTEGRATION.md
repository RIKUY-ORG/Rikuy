# Rikuy Frontend Integration Guide

## Stack
- **Chain**: Rikuy Chain L3 (Arbitrum Orbit, Chain ID `313370`)
- **Auth**: Privy embedded wallets
- **Identity**: Reclaim Protocol (ciudadaniadigital.bo)
- **Backend**: Express API at `VITE_BACKEND_API_URL`
- **Legal framework**: Ley 974 (Unidades de Transparencia y Lucha Contra la Corrupcion, Bolivia)

---

## Anonymous Report Flow (Ley 974 Compliant)

### `POST /api/reports` (multipart/form-data)

**Headers:**
```
x-user-address: <privy embedded wallet address>
```

**FormData fields:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `photo` | File (JPEG) | Yes | Image evidence (EXIF auto-stripped by backend) |
| `category` | string ("0"-"4") | Yes | Category ID |
| `accusedEntity` | string (1-200) | **Yes** | Identification of accused (person, title, institution) — Ley 974 |
| `incidentDate` | string (ISO date) | **Yes** | When the incident occurred — Ley 974 |
| `detailedDescription` | string (50-2000) | **Yes** | Detailed account of facts — Ley 974 "Relacion de hechos" |
| `evidenceDescription` | string (max 500) | No | What the photo evidence shows |
| `description` | string (max 500) | No | Short description (backward-compat, use `detailedDescription` instead) |
| `citizenSignature` | hex string | No | EIP-712 typed data signature (see below) |
| `location` | JSON string | Yes | `{ lat, long, accuracy }` — Bolivia bounds enforced |

**Response (success):**
```json
{
  "success": true,
  "reportId": "0x...",
  "contentHash": "0x...",
  "status": "confirmado",
  "recompensa": { "puntos": 0, "mensaje": "..." },
  "mensaje": "Denuncia registrada con validez legal (Ley 974)...",
  "blockchain": {
    "transactionHash": "0x...",
    "blockNumber": 12345,
    "arkivTxId": "0x...",
    "gasUsed": "...",
    "gasCost": "..."
  }
}
```

The `reportId` is the canonical on-chain ID. The `contentHash` can be used to verify data integrity against the Stylus contract. The `arkivTxId` references the full metadata stored for 10 years.

The backend handles: IPFS upload, AI image analysis, contentHash v2 generation (includes all legal fields), Arkiv storage, commitment generation, EIP-712 verification, nullifier generation, and blockchain TX via gasless relayer.

## EIP-712 Citizen Signature (Optional but Recommended)

The citizen can sign the report data with their Privy embedded wallet for **non-repudiation** (digital proof that the citizen submitted this report). The signature is optional — reports work without it.

**Domain:**
```typescript
{
  name: 'Rikuy',
  version: '2',
  chainId: 313370
}
```

**Types:**
```typescript
{
  RikuyReport: [
    { name: 'contentHash', type: 'bytes32' },
    { name: 'category', type: 'uint16' },
    { name: 'accusedEntity', type: 'string' },
    { name: 'incidentDate', type: 'string' },
    { name: 'timestamp', type: 'uint256' }
  ]
}
```

**Implementation with viem + Privy:**
```typescript
import { useWalletClient } from 'your-privy-setup';

const signReport = async (walletClient, reportData) => {
  const signature = await walletClient.signTypedData({
    domain: { name: 'Rikuy', version: '2', chainId: 313370 },
    types: {
      RikuyReport: [
        { name: 'contentHash', type: 'bytes32' },
        { name: 'category', type: 'uint16' },
        { name: 'accusedEntity', type: 'string' },
        { name: 'incidentDate', type: 'string' },
        { name: 'timestamp', type: 'uint256' },
      ],
    },
    primaryType: 'RikuyReport',
    message: {
      contentHash: reportData.contentHash,
      category: reportData.category,
      accusedEntity: reportData.accusedEntity,
      incidentDate: reportData.incidentDate,
      timestamp: BigInt(Date.now()),
    },
  });
  return signature;
};
```

**Note:** The `contentHash` in the signature message must match the one generated by the backend. For the MVP, the frontend can skip the signature — the backend gracefully handles missing signatures.

## Recommended Frontend Form (Multi-step)

### Step 1: Photo Capture
- Camera capture (existing `foto.tsx` flow)
- `evidenceDescription` field: "What does this photo show?"

### Step 2: Incident Details (Ley 974 required fields)
- `accusedEntity` — Input: "Who are you reporting? (person, title, or institution)"
- `incidentDate` — DatePicker: "When did this happen?" (use `@heroui/date-picker`)
- `detailedDescription` — Textarea (min 50 chars): "Describe the facts in detail"
- `category` — Select (0-4)

### Step 3: Review & Submit
- Show summary of all data
- "Sign and submit" button (triggers EIP-712 signature + form submission)

**Suggested HeroUI components:** `@heroui/date-picker`, `@heroui/input`, `@heroui/select`, `@heroui/card`, `@heroui/button`

## Identity Verification Flow

### `POST /api/identity/verify` (JSON)

**Headers:**
```
Content-Type: application/json
x-user-address: <privy embedded wallet address>
```

**Body:**
```json
{
  "ci": "12345678",
  "fullName": "Juan Perez",
  "walletAddress": "0x..."
}
```

**Response (success):**
```json
{
  "success": true,
  "data": {
    "verified": true,
    "commitment": "0x...",
    "txHash": "0x...",
    "status": "VERIFIED",
    "verifiedAt": "2026-..."
  }
}
```

### `GET /api/identity/status?walletAddress=0x...`

Returns verification status for a wallet.

## Contract Addresses

See `frontend/src/config/contracts.json` for deployed addresses. After a fresh deploy via `script/DeployAllL3.s.sol`, this file is auto-generated.

Key contracts:
- **RikuyCoreV2** (Solidity, UUPS Proxy) — main entry point
- **ReportRegistry** (Solidity, UUPS Proxy) — stores report metadata
- **AnonymousReport** (Stylus/Rust, no upgrade) — immutable anonymous report storage
- **CitizenZkVerifier** (Solidity) — Reclaim proof verification
- **GovernmentRegistry** (Solidity) — government entity management

## Reclaim Verification (on-chain)

The `ReclaimVerification` component (`frontend/src/components/ReclaimVerification.tsx`) handles on-chain ZK verification via `CitizenZkVerifier.verifyProof()`.

**Gap**: After on-chain verification succeeds, the frontend should ALSO call `POST /api/identity/verify` with the user's CI and name to register the anonymous commitment in the backend. This step is currently not wired up.

## Legal Compliance Notes (Ley 974)

The report system implements the requirements of Bolivia's Ley N. 974:

1. **Relacion de hechos** (Art. 18) → `detailedDescription` (min 50 chars, stored in Arkiv + hashed on-chain)
2. **Identificacion del denunciado** (Art. 18) → `accusedEntity` (stored in Arkiv + hashed on-chain)
3. **Temporalidad** (Art. 18) → `incidentDate` (stored in Arkiv + hashed on-chain)
4. **Prueba** (Art. 18) → `photo` (IPFS) + `evidenceDescription` (stored in Arkiv + hashed on-chain)
5. **Inmutabilidad** → `contentHash` v2 stored in Stylus contract (no upgrade mechanism)
6. **Non-repudiation** → Optional EIP-712 citizen signature

The `contentHash` stored on-chain is: `keccak256(JSON.stringify({ v:2, ipfsHash, fileHash, category, accusedEntity, incidentDate, detailedDescription, evidenceDescription, ts }))`. Any alteration to any field is cryptographically detectable.
